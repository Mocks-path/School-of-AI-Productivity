Week 1 · Lesson 04 · AI Excel

Automate the boring, report the rest.

You now know how to clean data and write formulas with AI. This lesson is about doing all of that without you — on a schedule, every Monday, while you sleep. But automation cuts both ways: done right it saves hours; done carelessly it silently reports wrong numbers for weeks. We will build the good kind, and stay honest about the traps.

01 / 04

Not everything deserves a robot

The most common automation mistake is automating the wrong task — spending three hours scripting something you do twice a year. A task is worth automating when three things line up: you do it often, it's painful or error-prone by hand, and the underlying data is stable (same columns, same layout, every time).

Frequency is the obvious one: a report you build every Monday will repay a script within a month; a one-off cleanup never will. Pain is about human cost — thirty minutes of mind-numbing copy-paste is worth removing even at the same frequency, because tired humans make quiet mistakes. Stability is the sneaky one everybody forgets: automation only works if next week's file looks like this week's. If your source keeps changing shape, a script just breaks in new and creative ways.

Multiply those three and you get a rough automation score. High on all three? Build it today. High on frequency and pain but low on stability? Fix the source first, or you're automating a moving target. Click a task below to see how it scores.

Four tools, four jobs — in plain English

Microsoft gives you several ways to automate Excel, and beginners waste weeks picking wrong. You don't need to master all four. You need to know which one fits the job in front of you. Here they are, honestly compared — click a tab.

The short version: Power Query is for repeatedly reshaping and cleaning imported data. Office Scripts is for automating steps inside a modern Excel workbook, and it plays nicely with the cloud. Power Automate is the scheduler and connector that ties Excel to email, Teams, and other apps. Macros / VBA is the old, powerful, desktop-only workhorse — still everywhere, but the past rather than the future. Pick by where your data lives and what you're trying to trigger.

Figure 2 · The Excel automation toolkit, compared
Power QueryNo code · Beginner-friendly

The data janitor that remembers

You clean a messy import once — split columns, remove junk rows, fix dates — using menus, not code. Power Query records every step. Next month, drop in the new file, hit Refresh, and it re-runs the whole cleanup instantly. It is the single highest-value automation tool most beginners never open.

Reach for it when

You import the same kind of messy data regularly and need it reshaped the same way every time — especially exports from other systems.

Strong points
  • No coding — all point-and-click
  • Tolerates messy, changing source data
  • Steps are visible and editable
Trade-offs
  • Only for import/transform, not full logic
  • Menu maze until you learn it
  • Won't send emails or schedule itself
Office ScriptsLight code · Modern Excel

Record-and-replay for the cloud era

The modern successor to macros, built for Excel on the web and Microsoft 365. You can record actions or write short TypeScript, and — crucially — AI is genuinely good at generating these from a plain description. They run in the cloud and connect straight into Power Automate for scheduling.

Reach for it when

You're on Excel for the web or M365 and want to automate steps inside a workbook, then hand it off to run on a schedule.

Strong points
  • Works in the browser and cloud
  • AI writes them well from a description
  • Slots into Power Automate for scheduling
Trade-offs
  • Needs a Microsoft 365 business plan
  • Not available in old desktop-only Excel
  • Some light TypeScript to read/tweak
Power AutomateLow code · The scheduler

The wiring between apps

Power Automate is less about Excel itself and more about when and what next. It's the tool that says "every Monday at 8am, run this Office Script, then email the result to the team." It connects Excel to Outlook, Teams, SharePoint and hundreds of other services with drag-and-drop steps.

Reach for it when

You need something to happen on a schedule or in response to an event — and to move results between Excel and email, Teams, or files.

Strong points
  • Scheduling and triggers built in
  • Connects Excel to email, Teams, files
  • Mostly visual, drag-and-drop
Trade-offs
  • Overkill for changes inside one sheet
  • Can get fiddly with complex conditions
  • Licensing tiers can be confusing
Macros / VBACode · Legacy but everywhere

The old workhorse still pulling carts

VBA is the classic macro language baked into desktop Excel for decades. It's powerful, runs entirely on your machine with no extra licence, and there's a mountain of examples online. But it's desktop-only, doesn't run in Excel for the web, and Microsoft is steering new work toward Office Scripts instead.

Reach for it when

You live in desktop Excel, can't use cloud tools, or you're maintaining a macro that already exists and works.

Strong points
  • No extra licence — built into desktop Excel
  • Very powerful, decades of examples
  • Runs fully offline on your machine
Trade-offs
  • Desktop-only — no web or cloud
  • Macro files can trigger security warnings
  • Microsoft is investing in Scripts instead

A one-line decision rule

If the job is cleaning imported data, start with Power Query. If it's steps inside a modern cloud workbook, use Office Scripts. If it's "do this on a schedule and email someone", that's Power Automate. And if you're on old desktop Excel with no cloud, VBA is still a perfectly good answer — just know it's the road behind you, not ahead.

Describe it, and AI writes the script

Here's the shift that makes automation beginner-friendly: you no longer have to know how to write an Office Script or a macro. You describe what you want in plain English, and AI writes the code. Your job moves from author to editor — reading, testing, and sanity-checking what it produced.

The trick is describing the task the way you'd brief a careful assistant: name the sheet, the columns, and exactly what "done" looks like. Vague requests get vague scripts. Pick a task below and watch a plausible Office Script appear. Read it — you don't have to write it, but you absolutely must be able to follow roughly what it does.

The part you cannot skip: reading it

  
AI-written scripts are usually right, but "usually" is doing heavy lifting. It might target the wrong column, assume your header is on row 1 when it's on row 3, or hard-code a value that changes. You don't need to write TypeScript — but before you trust a script with real data, read it line by line and ask: does this touch the sheet I think it touches, and would I notice if it did the wrong thing? Then test it on a copy. Always a copy.

Automate boldly, but guard carefully

  
Every step above can run untouched for months — which is exactly the danger. A silent pipeline reporting wrong numbers is worse than no report at all, because everyone trusts it. Automation earns that trust only if you build it defensively. Before you let any of this run unattended, walk the checklist below. Tick each one honestly.


  

    

      Figure 6 · The safe-automation checklist
      

        
        
      

    

    

      

        
✓

        
Test on a copy — never the original
Run any new script on a duplicate file first. If it does something dumb, it destroys the copy, not your real data.

      

      

        
✓

        
Read the script before trusting it
AI-written code is usually right, not always. Follow it line by line and confirm it touches the sheet and columns you expect.

      

      

        
✓

        
Assume the layout will change one day
Automation breaks when someone adds a column or renames a header. Build in a check, or expect the day it silently misfires.

      

      

        
✓

        
Add a sanity check to the output
Have the report flag the obvious — "total is negative" or "row count dropped 90%." A robot that shouts when confused is a safe robot.

      

      

        
✓

        
Keep a human in the loop
Even a ten-second Monday skim catches the failure a fully hands-off pipeline would hide for a month.

Why "test on a copy" is the whole game

  
Almost every automation horror story ends the same way: a script ran on the real file, did exactly what it was told, and what it was told was subtly wrong. Manual mistakes are loud — you see the mess. Automated mistakes are quiet and repeat perfectly, every Monday, until someone notices the numbers stopped making sense. A copy costs you thirty seconds. Skipping it can cost a quarter of trusted reports.






  
What to carry forward

  
Automation is leverage, not magic. Automate tasks that are frequent, painful, and stable — and negotiate away the unstable ones. Match the tool to the job: Power Query cleans, Office Scripts act, Power Automate schedules, VBA holds the fort on old desktops. Let AI write the code, but never stop reading it. And build every pipeline as if it will one day be quietly wrong — because eventually it will.
